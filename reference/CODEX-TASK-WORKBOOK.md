## Decisions and dead ends

- First-viewport decision: lead with the paper's actual 2017 translation task and explain why the architecture mattered before showing the wider LLM history.
- Copy decision: replace metaphorical or self-referential framing with dates, tasks, benchmark directions, mechanism, and bounded claims.
- Harness decision: detect exact fixed-width `w-[Npx]` tokens so `max-w-[1120px]` remains a valid fluid container constraint.
- Rejected semantic CSS layer: it duplicated Tailwind responsibilities and made the no-custom-class rule harder to enforce.
- Routing dead end: automated continuation turns lacked native context; after `/goal resume`, the current turn supplied an accepted context and allowed scoped inline work.
- Design correction: the previous brief-only hero removed the cover identity and made the title dominate the viewport. The replacement gives the cover a bounded panel and gives the chapter brief a parallel column with visible facts.
- Reader-model correction: “attention directly calculates token relationships” was too compressed. The page now explains that translation depends on relationships between words before introducing `attention` as the way to retrieve relevant information.
- Reporter-voice correction: the homepage's “do not memorize terms first” and “start with the problem” directives were removed. The replacement states the RNN sequencing constraint and lists the concrete research questions the chapter answers.
- Information-architecture correction: repeated “first paper” blocks were removed from the homepage. The feature lead carries the paper once; subsequent sections add new information rather than restating it.
- Skill fallback: the requested `enterprise` skill is not installed or discoverable in this environment. `design-system-architect` is the available owner for the same UI, responsive, and accessibility scope.
- Article-order decision: author identity is a late-stage context block, not the lead. The opening must establish the translation problem with an ELI5 example and diagram before naming the people behind the paper.
- ELI5 correction: the human-translator analogy was removed after visual review. The final explanation starts with words becoming numbers, shows the actual state dependency and parallel input calculation, then states that decoder generation remains sequential.
- Global skill decision: `/Users/gloomcheng/.agents/skills/eli5` is a symlink to the existing verified nested source, avoiding a second copy while making the skill directly discoverable.
- ELI5 decision: explain the computation directly with the sentence example and a small dataflow. The page defines Query, Key, and Value at the point where they are used, then shows the weighted sum rather than asking the reader to infer it from a metaphor.
- Image decision: use built-in imagegen for a text-free draft only after the user requested image2; reject it when visual review shows that it cannot explain the mechanism. The production diagram is native SVG with exact labels, while the surrounding HTML carries the accessible explanation.
- Editorial-layout decision: the report opens with a readable lead column, then gives the visual evidence its own full-width measure. The headline and diagram no longer compete as equal panels.
- ELI5 presentation decision: do not label a paragraph or diagram as ELI5. Write the simple explanation into the story itself, then introduce the formal term only after the reader can name the action in ordinary language.
- Long-case decision: use a multi-sentence Chinese scenario about a graduate student submitting a research proposal. It is a worked teaching case, explicitly marked as such, and is not presented as a paper quotation or an author's lived account.
- Causal-copy decision: explain “memory insufficiency” as fixed-width hidden-state compression and a long recurrent path, then explain self-attention as direct weighted retrieval from per-position data. Do not use “long-distance relations are hard” without showing the intervening positions.
- Verification timing decision: browser/render-level checks are deferred to pre-commit at the user's request; current work remains focused on copy and source-bound logic.
- Figure decision: make a diagram or table when the reader must track three or more positions, an ordered path, a before/after state, or a numerical transformation. The graphic must use the case's actual terms, show direction and output, and have adjacent prose that explains what the reader is seeing.
- Review ownership decision: Astra writes the reusable project skill; Sol performs the independent article read; the parent owns integration and does not present an audit as a completed fix.
- Typography decision: use standard Tailwind font-size utilities only; arbitrary `text-[...]`, `leading-[...]`, SVG `font-size`, and inline font-size values are out of scope. Standard `text-sm` and `text-xs` are for labels, not a mandate to shrink substantive prose.
- Deep-research decision: support the predecessor history with the primary 2014 sequence-to-sequence, 2014 alignment-attention, and 2015 attention-NMT papers; keep their limits visible instead of using the 2017 paper as evidence for every earlier stage.
- Case-integrity decision: keep `受訪者同意書` and `那份同意書` as the same referent across the source passage, English translation, prose, formula, and diagram; do not mix in the removed `那份文件` or `his notebook` example.
- Diagram decision: use the complete case position order and draw the recurrent path through intermediate states beside the direct self-attention comparison; the diagram is required because the reader must track multiple positions and a changing state.
